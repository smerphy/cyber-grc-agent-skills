# NIST SP 800-53 Rev. 5 — Security and Privacy Controls

## At a glance

| Attribute | Detail |
|---|---|
| Publisher | NIST (U.S. National Institute of Standards and Technology) |
| Current major revision | Rev. 5 (September 2020); maintained with patch releases (e.g., Release 5.1.1, November 2023) |
| Full title | Security and Privacy Controls for Information Systems and Organizations |
| Structure | 20 control families, two-letter identifiers; base controls plus control enhancements |
| Baselines | Defined separately in SP 800-53B: Low, Moderate, High security baselines + a Privacy baseline |
| Assessment guide | SP 800-53A (assessment procedures) |
| Legal anchor | Mandatory for U.S. federal information systems under FISMA / OMB Circular A-130 |
| Key derivatives | FedRAMP baselines; SP 800-171 (CUI in nonfederal systems); CMMC |
| Cost/licensing | Free; machine-readable (OSCAL) versions published by NIST |

## What changed in Rev. 5 (still relevant when reading older mappings)

- Controls became **outcome-based** — the phrase "the organization" / "the information system" was removed from control language so controls apply to any entity, not only federal agencies.
- **Privacy was integrated** into the main control catalog (previously a separate appendix), adding the PT family and privacy-relevant controls throughout.
- **Supply chain risk management** became its own family (SR).
- Baselines were **moved out** of the catalog into SP 800-53B.
- Many older crosswalks still reference Rev. 4 identifiers; check the revision before trusting a mapping.

## The 20 control families

| ID | Family | Scope in one line |
|---|---|---|
| AC | Access Control | Account management, least privilege, separation of duties, remote access, session controls |
| AT | Awareness and Training | Security/privacy literacy training, role-based training, training records |
| AU | Audit and Accountability | Audit log content, retention, protection, review, time synchronization |
| CA | Assessment, Authorization, and Monitoring | Control assessments, authorization to operate (ATO), POA&Ms, continuous monitoring |
| CM | Configuration Management | Baseline configurations, change control, least functionality, software inventory |
| CP | Contingency Planning | Contingency/DR plans, backups, alternate sites, testing |
| IA | Identification and Authentication | Identity proofing, authenticators, MFA, non-person entities |
| IR | Incident Response | IR plan, training, testing, handling, reporting, incident monitoring |
| MA | Maintenance | Controlled maintenance, maintenance tools and personnel, nonlocal maintenance |
| MP | Media Protection | Media access, marking, storage, transport, sanitization |
| PE | Physical and Environmental Protection | Physical access, visitor control, power, fire, environmental monitoring |
| PL | Planning | System security/privacy plans, rules of behavior, security architecture |
| PM | Program Management | Organization-level program controls: risk strategy, inventory, workforce, insider threat |
| PS | Personnel Security | Screening, termination, transfer, sanctions, third-party personnel |
| PT | PII Processing and Transparency | Authority to process PII, consent, privacy notices, special categories (new in Rev. 5) |
| RA | Risk Assessment | Risk assessments, vulnerability monitoring/scanning, criticality analysis |
| SA | System and Services Acquisition | SDLC security, acquisition process, developer security requirements, external services |
| SC | System and Communications Protection | Boundary protection, cryptographic protection, network security, isolation |
| SI | System and Information Integrity | Flaw remediation, malicious code protection, monitoring, input validation |
| SR | Supply Chain Risk Management | SCRM plans, supplier assessments, provenance, component authenticity (new in Rev. 5) |

Notes:

- **PM controls are deployed organization-wide**, not per-system; they are not allocated to the Low/Moderate/High baselines but are expected as part of the program (and several appear in the privacy baseline).
- Control numbering is family + number: `AC-2` (Account Management), `IR-8` (Incident Response Plan), `SC-7` (Boundary Protection).

## Control enhancements

Each base control may have numbered **enhancements** that add rigor or functionality, written as `AC-2(1)`, `AC-2(13)`, etc. Enhancements are not optional flavor text: baselines select specific enhancements, and higher baselines mostly differ from lower ones by which enhancements they add. Example: `IA-2` (Identification and Authentication) is in all baselines, but MFA-related enhancements such as `IA-2(1)` and `IA-2(2)` are what put multifactor requirements into scope. When mapping or assessing, always record the enhancement number, never just the base control.

## Organization-defined parameters (ODPs)

Many controls contain bracketed placeholders — "[Assignment: organization-defined frequency]", "[Selection: ...]" — that the implementing organization must fill in. Consequences:

- A system security plan (SSP) is incomplete until every applicable ODP is assigned a concrete value (e.g., AU log retention period, account inactivity threshold, scan frequency).
- Programs like FedRAMP **pre-populate many ODPs** with mandated values; do not assume the organization gets free choice in those contexts.
- In gap assessments, unfilled or undocumented ODPs are findings in themselves — a control "implemented" with no defined parameter is untestable. See [../../skills/control-testing/SKILL.md](../../skills/control-testing/SKILL.md).

## Baselines (SP 800-53B) and tailoring

SP 800-53B allocates controls and enhancements to three **security baselines** — Low, Moderate, High — selected according to the system's FIPS 199 impact categorization (confidentiality/integrity/availability, high-water mark), plus a **privacy baseline** applied wherever PII is processed regardless of impact level.

Tailoring is expected, not exceptional: organizations scope out non-applicable controls, apply compensating controls, assign ODP values, and add controls for specific threats. All tailoring decisions must be documented and justified in the SSP.

## Ecosystem: FISMA, FedRAMP, RMF

- **FISMA** requires federal agencies to protect information systems; OMB policy operationalizes this via NIST standards — FIPS 199/200 plus SP 800-53 controls, assessed under SP 800-53A, run through the **Risk Management Framework** (SP 800-37: Prepare, Categorize, Select, Implement, Assess, Authorize, Monitor).
- **FedRAMP** is the U.S. government cloud authorization program. Its Low/Moderate/High baselines are built on the 800-53 baselines with added controls, mandated ODP values, and program-specific requirements (e.g., continuous monitoring deliverables, ConMon scanning). A cloud provider's "FedRAMP Moderate" claim implies an assessed 800-53-based control set — useful evidence in third-party reviews ([../../skills/third-party-risk-assessment/SKILL.md](../../skills/third-party-risk-assessment/SKILL.md)).
- **Key artifacts** you will encounter: SSP (system security plan), SAR (security assessment report), POA&M (plan of action and milestones), ATO letter.

## SP 800-171 and CMMC (brief)

- **SP 800-171** protects **Controlled Unclassified Information (CUI)** in *nonfederal* systems — contractors and other organizations handling CUI, typically flowed down via contract clauses (notably DFARS 252.204-7012 in the U.S. defense supply chain).
- **Rev. 2** contains **110 security requirements in 14 families**, derived from the 800-53 Moderate baseline with federal-specific material removed.
- **Rev. 3** (final May 2024) realigns the requirements to 800-53 Rev. 5, restructures them with ODPs, and changes the requirement count and family set (adding families such as Planning, System and Services Acquisition, and Supply Chain Risk Management). Contracts specify which revision applies — check the clause, do not assume.
- **CMMC** (Cybersecurity Maturity Model Certification, U.S. DoD) adds an assessment and certification layer: Level 1 (basic safeguarding of FCI, self-assessed), Level 2 (aligned to the 110 requirements of 800-171 Rev. 2; self-assessment or C3PAO third-party assessment depending on contract), Level 3 (adds selected SP 800-172 enhanced requirements, government-assessed). CMMC scoring and POA&M allowances are program-specific — verify current DoD rules before advising.

## Using this in assessments

- **As a control catalog for non-federal orgs:** 800-53 is the most granular free catalog available and works well as a superset "backbone" for control mapping — map ISO 27001 Annex A, SOC 2 TSC, and CIS v8 into it rather than the reverse. See [../crosswalks/framework-crosswalk.md](../crosswalks/framework-crosswalk.md) and [../../skills/control-mapping/SKILL.md](../../skills/control-mapping/SKILL.md). For most commercial organizations it is too heavy to adopt wholesale; use CIS v8 ([cis-controls-v8.md](cis-controls-v8.md)) or ISO 27001 ([iso-27001-2022.md](iso-27001-2022.md)) as the primary framework instead.
- **Gap assessments:** always fix three coordinates before starting — (1) which revision (Rev. 4 vs Rev. 5 differ materially), (2) which baseline or overlay, (3) whose ODP values. See [../../skills/framework-gap-assessment/SKILL.md](../../skills/framework-gap-assessment/SKILL.md).
- **Reading vendor claims:** "NIST 800-53 aligned" without a baseline, revision, and assessment evidence is close to meaningless; ask for the SSP scope, assessment report, or FedRAMP authorization package.
- **Common pitfalls:** citing base controls when the requirement lives in an enhancement; ignoring the PM family because it isn't in a system baseline; treating 800-171 as "800-53 lite" without checking the applicable revision; forgetting the privacy baseline applies independently of the security impact level.
